# シグナル制約体系の再設計 — 3層への分離

作成: 2026-08-17

## 1. 目的

このプロジェクトの本体は、次の学習ループである。

> **④ AI が正確なシグナルを理由と共に提示 → ⑤ その売買結果を正確に記録 → ⑥ ⑤を AI に提示 → ④へ**

前提（相場観・ユーザーの判断）:
1. どんな相場にも適応する売買戦略は無い
2. 有利な売買戦略は相場や値動きにより違う
3. ②ゆえに、値動きを提示して AI が戦略を決めることが有利に働く可能性がある
4. AI に売買戦略の損益を提示することで、さらに良い戦略を作れる可能性がある

**根拠文はシグナルの一部である。** 理由が無ければ、⑥で結果を返しても何に帰属させるかが存在しない。
よって④が成立しないとループ全体が閉じない。**現状は④が成立していない。**

本設計は、④の前提である「正しいシグナルとは何か」を定義し直す。

### 2.3 合法解が存在しなかった

買いの指値レッグに課されていた量的制約を連立する。
記号: P=現在値、S1=指値の根拠にした節目、S2=損切りの根拠にした節目、d∈[5,10]、b=損切りの緩衝（**量が未定義**）。

```
節目の5〜10円内側      limitEntry = S1 + d,  d ∈ [5,10]
現在値から50円以上      P − limitEntry ≥ 50        ⟹ P − S1 ≥ 55〜60
損切りは別の節目の外側  損切り位置 = S2 − b,  S2 < S1
LC下限                  (S1 − S2) + d + b ≥ 55     ⟹ S1 − S2 ≥ 45〜50
```

**⟹ 現在値の下 100〜110円の範囲に、節目が2本必要。**

節目の実配置（1,200断面）:

| | 実測 |
|---|---|
| 最寄り節目までの距離（中央値） | 上 40円 / 下 45円 |
| 最寄り節目が 50円以内 | **82.8%** |
| 最寄り節目が 60円以内 | **89.8%** |
| 節目基準に忠実で両レッグ 50円以上 | **10.2%** |

**⟹ 89.8% の断面で合法解が存在しない。そして破るときどちらを捨てるかが、どこにも書かれていなかった。**

## 3. 「最低距離50円」の正体

**執行制約だった。** シグナル発生から売買命令を送るまでのラグの緩衝。
現在値±50円なら、価格が動いても指値・逆指値として成立する。

実測したラグ:

| 区間 | 中央値 | p90 | p99 |
|---|---|---|---|
| monitor ARM → trade2 受信 | **22ms** | 3.5秒 | 11.8秒 |
| **trade2 受信 → 発注決定** | **5.5秒** | 9.0秒 | 10.4秒 |
| 合計 | **6.7秒** | 9.2秒 | 19.8秒 |

**ラグの82%は trade2 の内部処理**であり、ネットワークではない。

閾値ごとの合法率（現在の配置 2,222レッグ）:

| 閾値 | 合法 |
|---|---|
| 10円 | **94.8%** |
| 25円 | 52.1% |
| 50円 | 28.0% |

trade2 には発注拒否の処理が既にある（第2レッグ拒否→第1レッグ取消→FLAT、確認タイムアウト→中止→post-abort検証）。
**再送や価格調整はせず、機会損失の方向に倒れる。**

**⟹ 執行の都合を戦略の指示として書いたことが、故障の根本原因だった。**

## 4. 設計原則

1. **制約は「強制」か「委任」の二値にし、中間を無くす。**
   プロンプトに書いてコードが見ていない制約は、守られないうえ、守られていないことに誰も気づかない。
   強制するならコードに書く。委ねるならプロンプトからも消す。
2. **量のない制約は制約として書かない。**
   「わずかに」「最小限だけ」「量は決めない」は、AI が不等式を閉じられず、コードも検証できない。助言として分離する。
3. **逃げ道を、すべての量的制約に、書き切る。**
   「一段先の節目へ → それでも上限に収まらなければ そのレッグを出さない → 両方なら見送り」。
   実測で、ここまで書けば合法解は 80.3% まで回復する（一段先へ逃がすだけなら 98.0% だが、
   200/400円の上限に当たって約2割が落ちるため）。
4. **自己検算の項目 ＝ 実際に強制する項目にする。**
   検算に載っている3項目は高遵守、載っていない1項目が72%違反。検算に載せることが実質的な強制になっている。
5. **委任で消える制約は、プロンプトからも消す。** 存在しない機構を AI に説明しない。
6. **方向には審判を置く。** 方向に効く要因の優先順位を明示する。
7. **委任は「値をAIが決める」であって「検査をやめる」ではない。**

### ★訂正（2026-08-18・実装後）: 最低距離の強制点

当初この設計書は「200/400 と同じ形＝ monitor の `checkSanity`（ARM時・refPrice基準）と trade2 の写しの**両方**」と書いた。
**実装は `server/signalTrade/decisions.ts` の `checkStaleLegs`（monitor 単独・live 価格基準・レッグ単位）を採った。**
実装のほうが正しい。理由は2つ:

1. **`checkSanity` は plan 全体を落とす。** 片方の脚が近すぎるだけで、もう片方の健全な脚まで捨てることになる。
   `checkStaleLegs` はレッグ単位で落とすので、設計原則3（「そのレッグを出さない → 両方なら見送り」）と整合する。
2. **緩衝が守るのは「ARM から発注が届くまで」のラグ**なので、plan 時点の `refPrice` ではなく
   **ARM 直前の live 価格**で測らなければ意味がない。`checkSanity` はプラン段では refPrice で走る。

**未達として残ること**: trade2 側に写しを置いていないので、当初意図した「ラグを挟んで2度測る」は**片側だけ**。
`server/signalTrade/sanity.ts` は trade2 と byte 同期の契約なので、そちらを触るなら trade2 と同時に出す必要がある。
★**将来 `sanity.ts` を同期する人は、最低距離がそこに無いことに注意すること**（`checkStaleLegs` にある）。
| 距離上限 200／400 | 両方にある | **プロンプトから削除**（コードは維持） |
| **tick 丸め（5円）** | **どこにも無い** | **新設** |
| クールダウン | spec に1箇所 | **プロンプトから削除** |
| 取引時間帯・鮮度・refDrift・武装期限・同一価格ブロック | コードのみ | 現状維持 |

### 層3：助言 — 渡すが「制約」と呼ばない

節目の強さ／緩衝「わずかに」／ブレイク新規のずらし「量は決めない」／テクニカルの使い方／
ギャップ禁止／「幅は結果であって出発点ではない」

**共通点は、すべて量を持たないこと。**

### 削除するもの

- 「※自動見送りは直近10分の±100円で判定する」 — **存在しない機構の説明**
  （トレンドveto を委任にすると機構ごと消えるのに、この一文だけが残る）
- レンジ無効時に残る range 条項（距離400/200・「上の2択に従え」＝参照先が存在しない）
- トレンド閾値の二重記述（spec は数値を与え、委任ノートは「閾値は課さない」と言う）
- v2 の「距離はシステムが検証します」 — 検証が存在しない（v2 を使う場合）

## 6. 別枠で塞ぐ欠陥（本設計とは独立・実弾に関わる）

1. **trade2 の `tradingEnabled` が死配線** — 毎tick評価され ctx に載るが、実弾の発注ループが一度も参照していない。
   「起動クリーンアップ中は新規を建てない」ガードが実効ゼロ。
2. **LC幅を trade2 が再検査しない** — `lcFloor`/`lcCeiling`/`lcHardMax` の識別子が trade2 に0件。
   monitor が壊れた幅を出しても、向きさえ合っていれば素通しで発注する。**LC幅は monitor が単一の強制点。**
3. **レンジ脚の `type` を誰も検査していない** — monitor・trade2 の両サニティが `side` と `entry` の上下しか見ない。
   `{side:'buy', type:'limit', entry:現在値+100}`（＝即約定する買い指値）が通過する。
   現在レンジは無効なので実害は出ていないが、**レンジを委任にした瞬間に開く**
   （かつ委任するとガード自体が無条件 true になる）。

## 7. 開いている論点

### 7.1 層2の「節目からの導出」をコードでどう検証するか

原理的には可能（`limitEntry` が levels のどれかの5〜10円内側にあるか）。
ただし現在の配置は距離15〜25円、節目は40〜45円なので、**いきなり強制すると大半が落ちて取引がほぼ止まる**。
記録のみにすると、本設計が明らかにしたとおり守られない。

**方針**: 層1（距離を10円へ）を先に直す。その圧力が消えれば AI は節目に素直に置けるようになるはずなので、
**その後の実データで「もし強制したら何%が通るか」を測ってから決める。**

### 7.2 ラグ 5.5秒をどうするか

必要な緩衝はラグに比例する。trade2 の内部処理 5.5秒を縮めれば、緩衝も比例して縮む。
本設計の範囲外だが、10円という値の妥当性はこの数字に依存する。

## 8. 移行の順序

1. **層1を直す**（距離をプロンプトから削除・コードで10円を強制・tick丸め新設・距離上限をプロンプトから削除）
2. **削除するものを削除する**（存在しない機構の説明・死んだ range 条項・二重記述）
3. その後の実データで **7.1 を判断**
4. **層2の印字を整理**（LC下限の20回を削減し、他の制約が押しのけられない配分にする）
5. **原則6（方向の審判）** を書く
6. 別枠の欠陥3件を塞ぐ

★**1コミット1変数。** v0.9.70 が画像・プロンプト契約・プロバイダ到達性を同時に変えたため、
この期間最大の品質劣化が帰属不能になった。同じことを繰り返さない。

## 9. 検証の作法

- 変更は生成器の**候補腕**で先に測る（本番と同じプロバイダ連鎖・同じ市場断面・実弾リスクゼロ・追加コストなし）
- 主指標: 距離の違反率／LC幅の**相異なる値の種類数**（平均だと「下限＋一定」への移行を見逃す）／
  両レッグ同幅率／根拠文に理由がある割合／`none` 率
- **母集団（期間・腕・モード）を必ず揃えてから比較する**
- 「テストが緑」を完了の証拠にしない。実データでの発火数を示す

## ★訂正2（2026-08-18・実測）: 「層1は絶対にプロンプトに書かない」は1点で否定された

原則1と層1の割り当ては「最低距離はプロンプトから全削除し、コードだけが持つ」としていた。
**これを候補腕 `prompt-v1d`（= v1 マイナス最低距離の記述）で実測したところ、主指標が悪化した。**

同一 epoch+cycle の対応ペア **209件**（2026-08-18・同一設定）:

| 指標（出す前に決めた） | current(v1) | prompt-v1d | |
|---|---|---|---|
| **両レッグ同幅率**（主指標・下がるほど良い） | 76.4% | **84.7%** | 悪化 |
| 距離<50 の割合 | 58.4% | **66.4%** | 悪化（McNemar **p=0.0037**） |
| 距離の中央値 | 40円 | **30円** | 悪化 |
| LC幅=55固着 | 36.1% | **44.3%** | 悪化 |
| 見送り率 | 7.2% | 9.6% | 悪化 |

**予測が外れた。** 「89.8% の断面で合法解が無いという矛盾を取り除けば、AI は節目（中央値40〜45円）に
素直に置くようになる」と考えたが、実際は**節目から遠ざかり現在値に近づいた**（40→30円）。

### 訂正の内容

**最低距離の記述はプロンプトに残す。** コードの強制（10円）とは別に、**「置き方の誘導」として働いている**。

- **プロンプトの 50円** = 誘導。「これくらい離して置け」という置き方の指針
- **コードの 10円** = 執行の下限。「これ未満は発注として成立しないので落とす」

**目的が違うので併存してよい。数値の不一致は意図的**であり、揃える必要はない。
原則1（強制か委任かの二値）は、**「プロンプトに書いてよいのは誘導まで。強制はコードが持つ」**と読み替える。
プロンプトだけにあって誰も強制しない制約を作らない、という趣旨は変わらない。

### 次に測ること

候補腕を **`v1e` = v1 マイナス「距離の上限 200/400円」の記述**（コードの強制は残す）に載せ替えた。

きっかけは、v0.9.83 で**死んだ記述だけ**を消したあとに v1 自身が改善して見えたこと
（距離<50 が 71.2%→58.4%、同幅率 88.1%→76.4%、距離の中央値 30→40円）。
★**ただしこれは日をまたいだ比較で交絡している。**epoch の切替がセッション日の境界と一致したため、
同一日内の前後比較は取れなかった。**観察であって発見ではない。**

仮説「競合する距離の数値（200/400）が、生きている距離規則を押しのけていた」を、
同一 epoch・同一 cycle の並走で交絡なしに測る。改善しても悪化しても情報になる。
