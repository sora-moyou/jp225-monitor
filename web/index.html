設定（APIキー）

最低1つ設定すれば動作。複数設定で 429 時に自動フォールバック。
保存先: ~/.jp225-monitor/config.json (ローカルのみ、送信されません)

APIキー（無料）
まずは無料キーだけで動きます。おすすめは Gemini（画像対応・無料枠が広い）。Groq はテキスト専用で高速な予備。
モデル欄は空欄でOK（既定値が使われます）。提供元がモデルを廃止/改名したときや、「キーを検証」で「このキーでは使えません」と出たときだけ、一覧に出たモデル名を入れて保存してください（アプリの更新は不要です）。
APIキー（有料）
Kimi はキーごとに使えるモデルが違います（"Not found the model … or Permission denied"）。404 が出たら「キーを検証」を押すと、そのキーで使えるモデルの一覧が下に出るので、そこから選んでこの欄に入れて保存してください。
OpenAI は画像対応で安定運用の要（少額課金）。Kimi はテキスト専用の安い従量課金で、無料枠が枯渇/失敗したとき OpenAI より先に使われる予備（画像は非対応）。Web検索キーは任意: チャットの Web 検索で使う専用キーで、空欄なら上の Gemini キーを流用します（課金 Gemini グラウンディング用）。Gemini キーが無い/枠切れでも、OpenAI キーがあれば OpenAI 側で Web 検索できます。
通常は空欄＝変更なしです（うっかり全消去しないための既定）。誤って貼ったキーを取り消したいときだけ、その欄を空欄にしたままこれをチェックして保存してください。対象は上の Gemini / Groq / OpenAI / Kimi / Web検索用 の5欄で、入力した欄はその値で保存されます（消えるのは空欄の欄だけ）。このチェックは保存後・画面を開き直すたびに外れます。
各プロバイダのモデル一覧(GET /v1/models)を取得して、①キーが有効か ②設定中のモデルがそのキーで使えるかを確認します（トークンは消費しません）。保存済みキーが対象です。モデルが使えない場合はそのキーで使えるモデルの一覧を出すので、上のモデル欄に入れて保存してください。
各キー左のマーク: 🟢 有効(設定済) / 🟡 待機中(429=枠切れで一時休止) / ⚪ 未設定 ／「キーを検証」後: ✅ キーもモデルもOK / ⚠️ キーは有効だがモデルが使えない / ❌ キーが無効(401等) / ⚪ 未設定。
※モデル一覧に対応していない提供元だけ、従来どおり極小(1トークン)の ping で判定します。
提案生成器（分析用・実弾とは別プール）
オフのあいだ、同梱の生成器は待機するだけです——LLM を1回も叩かず、台帳にも1行も書きません。オンにすると2分ごとに提案を作り始め、LLM の予算を消費します。画面右上の Ge ドットで状態が分かります（⚪無効／🟡有効だが記録なし／🟢標本が溜まっている／🔴前提が崩れて停止＝理由はマウスを乗せると出ます）。
分析用の「提案生成器」は実弾（A）とは別のプロバイダ・プールで動きます。専用キーを入れると上流のクォータまで分けられます。空欄ならこの上の共通キーへ黙ってフォールバックします——その状態でも生成器は動きますが、実弾と同じ枠を消費します。各行の表示で「今どちらのキーが効いているか」を確認してください。
★専用キーを設定しても、同じアカウントのキーでは提供元側の枠は共有されます（多くの提供元でレート制限は組織／プロジェクト単位です）。完全に分けるには別アカウント、または実弾とは違う提供元を使ってください。
生成器プールが実際に使うキーで極小(1トークン)の ping を1回ずつ送ります。専用キーがある行は専用キーで、「共通キーを使用中」の行は共通キーで検証します（後者は実弾と同じ枠を消費します）。上の「キーを検証」は従来どおり共通キー（実弾側）が対象です。
2分間隔でフルカバーすると約 600 回/取引日、生成器2本＋対照の運用見込みは約 1,584 回/日。この予算は「腕」（決済仕様の変種）ごとに独立して効きます——共有にすると先に叩いた腕が取引日の残りを食い切り、標本が日中前半に偏るためです。既定は 800 / 腕（旧: 全腕で共有する 200）。上限に達した腕は停止し、記録に残ります（無音で縮退したりモードを書き換えたりはしません）。空欄で既定に戻ります。

詳細設定

Web検索モデル
Gemini キーで Web 検索するときのモデル。grounding（Google 検索連携）対応が必要（Gemini 3.x 系）。空欄で既定 gemini-flash-latest。
Gemini キーが無い/枠切れのとき OpenAI で Web 検索するモデル。Web 検索対応モデル（search-preview 系）を指定。空欄で既定 gpt-4o-mini-search-preview。
AIエントリー
各項目は「手動(数値/enumを強制)」か「AI委任(この値をAIが決める=該当制約を課さない)」を選べます。既定は全て手動＝現状の挙動のまま。1項目ずつ AI に倒して、書き出し(どの設定でエントリーしたか)で効果を検証できます。
★v0.8.2: 各行は A(実売買・trade2が追従) と B(📝紙のみ・並走比較) を横並びで設定します。B は空欄/「A追従」なら A と同じ設定で動きます(B だけ差分を付けて比較)。B は実売買に一切渡りません。
AIエントリーの損切り幅とバイアス(狙う方向)の設定です。変更したら「保存」を押すと、次のエントリーから反映されます。
手動＝設定した数値を必ず守らせます（コードで判定し、外れた注文は出しません）。AI委任＝この項目はAIが場面ごとに決めます（設定値は使いません）。
★初期LC下限だけは委任の対象外です（そのためモード選択がありません）。ここに入れた数値はコードで必ず強制します（決済ロジックが成立するための前提条件のため）。

上の設定とは独立した最後の安全網。左のチェックが入っていれば、どんな場合でもこの幅を超える損切りは出しません。★チェックを外しても上限が無くなるわけではありません：コード側の上限300円が常に残り（AIへの指示にも「コード上限300円」と伝わります）、「最大初期LC」が手動ならその値も引き続き効きます。既定=有効・159円。
AI にチャート画像(TradingView の撮影)を送るかどうかです。送らない＝1枚も送らず、撮影(ヘッドレスChrome の起動)も行いません。半分だけ送る＝サイクルごとにランダムで半分の回だけ送り、「画像があると成績が変わるのか」を比べられるようにします(その分だけ課金も半分)。★全部送る設定はありません。
AI委任にすると、その項目の数値/enum強制を外し、AI が自分で決めます(プロンプトで委任を明示・根拠を述べさせる)。手動なら従来どおりコードで強制します(LC下限=下限未満のレッグ落とし / LC上限=超過レッグ落とし / バイアス=逆方向を見送り / トレンドveto=逆行フェードを落とす / クールダウン=決済後の再ARM抑止 / レンジ両面=on/off)。いずれもレッグが両方落ちれば見送り(none)になります。
★初期LC下限は委任の対象外です。「AI委任」を選んでもコードは下限を強制します(設定より優先)。理由: 決済は含み益が一定に達して初めて利益をロックしていく方式なので、下限より狭い初期LCは床が働く前に切られ、決済ロジックが構造的に成立しないためです。※これは明らかに前提の壊れた計画を止めるだけで、成績の改善を意味するものではありません。
★最大初期LCをAI委任にしても上限は完全には消えません: LC安全上限が有効ならその値、無効でも 300円(設定として指定できるLC幅の上限)を実効上限として残します。A は monitorのシグナルエンジンと jp225-Trade の両方(実売買)に反映されます。B は紙専用の並走比較のみで、実売買には一切渡りません。
★LC安全上限: 実弾の暴走を防ぐ最終安全網です。有効時は最大初期LCが手動でもAIでも、|エントリー−損切り| がこの円を超えるレッグを必ず落とします(最大初期LCのAI委任とは独立)。無効にするとハード上限なし=AI完全自由(明示的に選んだ場合のみ)。既定=有効・159円。
レンジ両面: レンジ判断時に上下両面のエントリーを出す(実験・紙で別枠計測)。フェード(指値両面)は過去検証+実データでも不利だったため、★実験終了(手動の既定OFF)。
★ドテン許可(AIが保有中に反転を判断してよい): 保有中に AI が「決済と同時に反対方向へ新規」した方がよいと判断した場面だけ、monitor が反転(=決済+反対新規)シグナルを出します。常に反転するわけではなく AI が都度判断します。既定=OFF(反転しない=従来どおり)。反転は通常の決済→別の新規とは区別して記録されます。
★レンジ未約定でブレイク再評価: レンジ両指値(逆張りフェード)が「平均約定所要 × 1.5」を超えて約定しないとき、AI に「両逆指値(ブレイク追随)へ切替 / 現状維持 / 見送り」を再判断させます。レンジを使う設定のときだけ実効(レンジ自体が既定OFF)。既定=ON。
★チャート撮影失敗でもテキストで継続: チャート画像(TradingView撮影)が ws-error 等で取れない時、1回リトライ後もダメなら画像なし(価格/レベル/指標のテキストのみ)で AI に戦略を作らせて取引を継続します。既定=ON(チャート障害で全停止するのを防ぐ)。OFF にすると撮影できない間は見送り(ストリクトvision=従来挙動)。
★AIにチャート画像を送る: 既定は送らないです。チャート画像はテキストに比べて桁違いに大きく、無料枠のプロバイダが使えない時間帯は有料プロバイダに全てかかるため、課金の主因になります。しかも画像が成績に効いているかは一度も測れていません(ほぼ全ての呼び出しに画像が付いていて、比較対象=画像なしの回が存在しないため)。「半分だけ送る」にすると、サイクルごとにランダムで半分の回にだけ画像を付けるので、課金を抑えたまま画像あり/なしを比較できます(どちらの群だったかは計画の台帳に記録されます)。全部送るモードは用意していません。
